# 08 — Checklists

Run the gate before working, the proposal before rewriting, and the exit before delivering. Everything in between is the workflow in SKILL.md.

## Gate checklist (step 1)

- [ ] **Mode:** improve · build from notes · draft from scratch · review only
- [ ] **Voice mode:** preserve · establish · match — and if establish, which register (`07-voice.md`)
- [ ] **The one reader** named. Not a segment. A person.
- [ ] **What that reader already believes** about this subject
- [ ] **Purpose and destination** of the piece
- [ ] **Constraints:** length, format, deadline, house style, things that must not change
- [ ] **What must not change** — claims, structure, terminology, legal constraints — asked and recorded
- [ ] **Questions worth asking** identified — at most three, each with your best-guess default

If nobody can answer, apply text-level changes only, leave substance-level items as labelled gaps in place, and say at the top what you left alone and why. Silence is never consent for a substance-level change.

## Proposal checklist (step 4) — before you rewrite anything

Nothing gets rewritten until this has been sent and answered. A recommendation applied without asking is a rewrite of the author's thinking wearing the clothes of an edit.

- [ ] Every finding sorted into **text-level** (how it says it) or **substance-level** (what it says)
- [ ] Text-level list summarised by kind, not itemised line by line
- [ ] Each substance-level item states: what you found, what it costs the reader, what you would do, **and whether it changes the author's meaning**
- [ ] Substance items **numbered**, so the author can accept some and refuse others
- [ ] At most three questions, each with a best-guess default
- [ ] Assumptions listed separately from recommendations
- [ ] Nothing in the list is a claim, number, example or offer you would be supplying yourself
- [ ] Sent. Now wait.

**Substance-level, for the avoidance of doubt:** adding or removing any claim, example, statistic, section or heading · reordering, merging or splitting sections · renaming a framework or its steps · changing the Point, status quo or stated cost · adding a call to action, price or next step · anything asserting something about the author's business, market, audience, offer or results · changing how the author addresses their reader, including person, gender, formality, or the word they use for their own clients.

**When in doubt, it is substance-level.**

## Frame checklist (step 5)

- [ ] **Point** written as one sentence
- [ ] **Status quo** = the Point inverted, in the reader's own words, phrased so they would nod
- [ ] **Cost** to this reader of keeping the status quo — real, not invented
- [ ] **Problem statement** filled in: *I am writing about ___ because I want to find out ___ in order to help my reader ___*
- [ ] Everything that does not serve it marked for cutting
- [ ] The **question** the piece answers, if the draft was organised around a topic

## Edit pass (steps 6–7)

Work top down. A fault at the top makes the ones below it irrelevant.

**Whole piece**

- [ ] Title is clear not clever, and uses one of the four curiosity triggers
- [ ] Introduction moves stability → instability across its six slots
- [ ] No repelling intro pattern (background→thesis, general→specific, gap→niche)
- [ ] A hook, if present, sets up the problem rather than merely being interesting
- [ ] Skim test passes: paragraph openings alone tell the story
- [ ] Conclusion returns to the opening problem and links it outward

**Sections**

- [ ] Each has an Index that states its Point and names its Key Terms
- [ ] Each section's Point does both jobs: controls its paragraphs, supports the Point above
- [ ] Point-first or Point-last chosen per unit — never both
- [ ] No accidental Point-last: no unit where the Point is buried mid-Discussion
- [ ] Headings built from concepts that recur inside the section
- [ ] Time jumps carry plain signals
- [ ] Set-ups have payoffs; payoffs have set-ups

**Paragraphs**

- [ ] Topic strip names a small set of related, important characters
- [ ] Each Discussion develops the Key Terms its Index announced — no dropped promises
- [ ] Two or three thematic strings run through each section
- [ ] Each paragraph uses a pattern that fits its job (constant theme, linking, super theme, theme preview)
- [ ] Linked passages pass the same-stage test
- [ ] Any varying-topic passage has an explicit index clause naming the umbrella
- [ ] Theme previews repeat exact key terms, no synonyms
- [ ] Handoffs intact: each sentence ends with something the next picks up

**Sentences**

- [ ] Main characters in subject positions
- [ ] Key actions in verbs
- [ ] Every surviving nominalization has one of the four reasons
- [ ] Short runway: intro phrase → short concrete subject → specific verb
- [ ] Long clauses and new technical terms at the end
- [ ] No long introductory clauses; verbs near their objects
- [ ] Passives kept only where they put old information first
- [ ] Meta-discourse replaced with questions, "as we have seen", or shared movement
- [ ] Labels replaced with evidence — or flagged as gaps
- [ ] Clichés gone
- [ ] Rhythm varies; read aloud

**Voice**

- [ ] Matches the mode set at the gate
- [ ] The one or two carrying attributes are present and consistent
- [ ] Nothing distinctive has been sanded off
- [ ] Read aloud: *fewer words?* and *would this voice say this?*

## Exit QA (step 8)

- [ ] Diagnostic script re-run; changes are in the direction you intended
- [ ] Skim test passes on the revised draft
- [ ] **Nothing invented.** No example, number, quote, source, scene or anecdote that the author did not supply
- [ ] Every gap you could not fill is named in the report, specifically enough to act on
- [ ] Any rule you deliberately broke is named, with the reader-experience reason
- [ ] The piece still sounds like whoever it is supposed to sound like
- [ ] Report is proportionate — the changes that mattered, not a catalogue
- [ ] **Every substance-level change in the output was approved at step 4.** If you found something new mid-rewrite, it is a proposal for the next pass, not something you already did
- [ ] What you deliberately left alone is stated, so the author knows it was a choice

## Review mode: the letter of response

When asked for critique rather than a rewrite, use this order. It is not politeness — **if you have not shown that you understood the intent, the author has no reason to accept the criticism.**

**1. What the piece is trying to do.** State it as clearly as you can, before anything critical. Aim for the author reading it and thinking *yes — that is exactly what I was trying to do.* That is what puts them in a position to hear the rest.

**2. What you would steal from it.** Name specific techniques that work and that you would use yourself. This forces your attention onto craft rather than fault-finding, and it tells the author what to protect when they revise.

**3. Only now, what is missing or not working.** Ordered by leverage: value and Point first, structure next, sentences last.

**4. The gaps only they can fill.** The material you cannot supply — the scene, the number, the judgment, the cost. Ask directly.

Two supporting habits worth passing to the author:

- **Read it twice.** Once as a reader, at normal speed, skimming where you would skim, stopping where you would stop — then put it down and record your reaction before analysing. Days later, read analytically.
- **Body-scan the reaction.** "This is boring" is data. Where does the boredom live? Which sentence is worst? How far does it extend? Locate it precisely, the way you would locate a pain rather than getting up, and only then work out how the effect is produced.
