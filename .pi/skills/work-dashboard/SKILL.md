## Prerequisites

- The app runs as the Docker container `work-dashboard`. Start or rebuild it with `make up`. Check with `curl -fsS http://127.0.0.1:8787/healthz`; it answers `{"status":"ok"}`.
- `/Users/saschametzger/Projects/Private/work-dashboard/bin/wd` is the CLI. It wraps `docker exec -i work-dashboard /wd "$@"`, so it needs the container, not a host Go install.
- REST base: `http://127.0.0.1:8787/api/v1`. The contract is `openapi.yaml` (`/Users/saschametzger/Projects/Private/work-dashboard/bin/wd openapi`).
- Writes with a JSON body need `-H 'Content-Type: application/json'`. Without it the API answers 415 `Content-Type must be application/json`. File upload uses `application/octet-stream`.
- `/Users/saschametzger/Projects/Private/work-dashboard/bin/wd --help` lists every command; `/Users/saschametzger/Projects/Private/work-dashboard/bin/wd <command> --help` shows usage, flags and an example. Both work offline; the full reference is docs/cli.md, regenerated with `make cli-docs`.
- Add `--json` to any CLI command for one JSON object (an array for `ls`) on stdout. Without it you get short human text.
- `WD_URL` changes the server the CLI talks to (default `http://127.0.0.1:8787`).
- Errors with `--json`: stderr gets `{"error":"<message>","field":"<name or empty>"}`. Without it: `error: <field>: <message>`. Over REST the same body comes with the HTTP status (404, 409, 415, 422).
- Exit codes: 0 on success, 1 on any error (validation, not found, conflict, usage).
- Task statuses: `todo`, `doing`, `waiting`, `done`. Priority: `low`=1, `normal`=2, `high`=3 (the CLI accepts the words or the numbers). Dates: `YYYY-MM-DD`.
- An epic is a normal task. A task joins an epic through `--epic <task id>` (REST: `parent_id`).
- Project order: pinned projects first, then the rest, then archived ones. Inside each section `position` counts 1..k; `ls` and the overview follow it. Archived projects are unpinned with `position` 0 and cannot be pinned or moved (409).
- IDs are plain integers. A task id and a project id are different numbering spaces.

A repeating task always has a due date. Marking it done creates the next copy, due on the first rhythm date after today (missed days are skipped). The copy keeps title, epic, priority, tags, due note and notes; not links, files or "waiting for". The repeat moves to the copy.

`--tags` replaces the whole tag list (comma separated).

## Gotchas

- Delete needs archive first: `project rm` on an active project fails with 409 `archive the project before deleting it`. Tasks, links and files delete directly.
- `import` only works on an empty instance; otherwise 409 `import needs an empty instance`. Never wipe data to make room for an import without the human's go.
- Dates must be real `YYYY-MM-DD`; `12/01/2026` fails with `must be a real date like 2026-11-20` (field `due_date`).
- `repeat` errors (422): `status: done` and a non-empty `repeat` in one request (field `repeat`); clearing the due date of a repeating task (field `due_date`); `repeat` on a done task (field `repeat`). Complete first, then change the copy's repeat.
- Unticking a done repeating task does not remove its copy, and the reopened task no longer repeats. Delete the extra task by hand.
- `task ls` needs `--project`. `--status` is a client-side filter in the CLI; the REST list has no `status` parameter.
- `--done` takes `0`, `1`, `true` or `false`; anything else fails on field `done`.
- `project show` and `task show` print `key: value` lines without `--json`; use `--json` when you parse.
- Never run `docker compose down -v` or touch the `wd-data` volume: that deletes all data.
- For experiments, start a throwaway container with its own name, port and volume (see `scripts/smoke.sh`), and remove both afterwards. Do not run destructive commands against port 8787.
