# Sync Pi Config

Syncs the `.pi` directory between the project-local copy and the global `~/.pi/agent/` directory.

## Usage

```bash
npx tsx scripts/sync-pi-config.ts pull   # Global → Local
npx tsx scripts/sync-pi-config.ts push   # Local → Global
```

## What Gets Synced

All files under `.pi/` except:

| Path | Reason |
|------|--------|
| `auth.json` | Credentials |
| `sessions/` | Ephemeral state |
| `npm/` | Cached packages |
| `models.json` | Local model overrides; holds plain-text API keys, never mirrored |
| `trust.json` | Per-machine trust decisions |
| `AGENTS.md` | Project-local work contract (top-level only; nested `AGENTS.md` files, e.g. under `extensions/`, still sync) |
| `mcp-cache.json` | Global runtime cache (MCP), regenerated by the global runtime |
| `models-store.json` | Global runtime cache (model store), regenerated by the global runtime |
| `pi-cache-optimizer-stats.d/` | Global runtime cache (optimizer stats), regenerated by the global runtime |
| `mcp-project-approvals.json` | Per-machine MCP server approvals |
| `claude-bridge.json`, `claude-bridge-diag.log` | claude-bridge provider state, written by the global runtime |
| `zentui.json`, `themes/` | Per-machine UI preferences |
| `compact-tools-notices/` | pi-compact-tools release-notice markers |
| `sandbox-run/` | Live settings files of running sandboxed sessions; deleting one kills that session's bash |
| `sandbox.json` | The user's sandbox policy override (extra domains), per machine |

Sync leaves `sandbox-run/` files of crashed sessions behind. Files whose pid no longer runs are safe to delete by hand; never delete the file of a running session.

## Project-only extension files

`PROJECT_ONLY_EXTENSION_FILES` lists extension files (paths relative to `extensions/`) that stay in this repo until their rollout is decided. Today: `sandbox-bash.ts` and `lib/sandbox-bash.ts`.

- Push never copies them; pull never overwrites them; a manual global copy is neither updated nor deleted.
- The extension-directory pruning skips a local folder that holds one, even when the global folder carries `.pi-managed`.
- Smoke's drift check skips them while no global copy exists. A global copy that differs is reported as `differ`, because the global copy shadows the project copy.
- Matching is exact: `sandbox-bash-extra.ts` is a normal extension file.
- Rollout: remove the entry; the next push copies the file globally.

## File Modes

`push` keeps each file's mode (`chmod` to the source mode) and treats a mode-only difference as a change. Git skips a hook without its exec bit silently, so the synced `security/git-hooks/` must stay `0755`. `pull` is unchanged.

## Security Guard (`security/`)

`push` first imports `.pi/security/policy.ts` and `guard-core.ts`, compiles every pattern, and checks that reading `.env` is denied. If any step fails, push exits non-zero and writes nothing, so the last good global copy stays in place. PI, Claude, and every commit fail closed on a broken policy, so this check guards all three.

Sync only ships the files. Point git and Claude at them once, by hand. The hook runs `node` on `.ts` files, so it needs Node 22.18 or later.

1. Check that no global hook path is set. The output must be empty:

   ```bash
   git config --global --get core.hooksPath
   ```

2. Point git at the synced hooks and ignore file:

   ```bash
   git config --global core.hooksPath ~/.pi/agent/security/git-hooks
   git config --global core.excludesFile ~/.pi/agent/security/gitignore-global
   ```

3. Add the Claude hook to `~/.claude/settings.json` by hand. Append these entries to the existing `PreToolUse` and `UserPromptSubmit` arrays; leave every other key as it is:

   ```json
   {
     "hooks": {
       "PreToolUse": [
         { "matcher": "*", "hooks": [{ "type": "command", "command": "node \"$HOME/.pi/agent/security/guard-cli.ts\" || exit 2", "timeout": 30 }] }
       ],
       "UserPromptSubmit": [
         { "hooks": [{ "type": "command", "command": "node \"$HOME/.pi/agent/security/guard-cli.ts\" || exit 2", "timeout": 30 }] }
       ]
     }
   }
   ```

Undo:

```bash
git config --global --unset core.hooksPath
git config --global --unset core.excludesFile
```

Then remove the two entries from `~/.claude/settings.json`.

Check the install at any time (read-only; exit 0 when installed, 1 with the commands above when not):

```bash
node ~/.pi/agent/security/check-install.ts
```

### Installing repo hooks while the global hook path is set

Installers that ask git for the hooks folder (`git rev-parse --git-path hooks`), such as `graphify hook install`, get the global folder and write into it. Their hook then never runs, and the next push overwrites it. `pre-commit install` refuses to run at all while `core.hooksPath` is set. Hide the global config for that one command:

```bash
GIT_CONFIG_GLOBAL=/dev/null graphify hook install
GIT_CONFIG_GLOBAL=/dev/null pre-commit install
```

Both then write into the repo's own `.git/hooks/` (verified: graphify, and pre-commit 4.6.2). The global dispatcher runs those repo hooks after its own scan. Run these yourself: the guard blocks agents from hiding the global git config.

## settings.json

Merged, never overwritten. Shared keys: the source wins. Keys that exist only in the target are kept. `packages` are merged. `lastChangelogVersion` is per-machine and never copied.

## Skill Library

`skill-library/` is synced like any other managed path — mirrored in both directions, including the nested `skill-library/AGENTS.md` index and each skill's `references/` folder. Only the *top-level* `AGENTS.md` is excluded; nested `AGENTS.md` files (e.g. `skill-library/AGENTS.md`) still sync.

Mirror semantics apply: a `push` deletes skill-library files that exist only globally, and a `pull` deletes those that exist only locally. If you maintain the library in the global dir (see its own `AGENTS.md`), run a `pull` first so the local copy is current before you `push` anything else.

## Extension Directory Pruning

When syncing, extension directories under `extensions/` that exist in both global and local are pruned from the local copy — **but only if the global extension is marked as managed**.

### Managed Extension Marker

A global extension is considered "managed" (and therefore eligible for pruning) only if it contains a `.pi-managed` marker file:

```
~/.pi/agent/extensions/plan-mode/.pi-managed  ← managed, local copy gets pruned
~/.pi/agent/extensions/lib/                   ← no marker, local copy is preserved
```

### Why Marker-Based?

The marker approach replaces a hardcoded exclusion list. It:

- **Auto-works** for new directories — no config change needed
- **Self-documents** — the marker signals intent
- **Is reversible** — remove the marker to stop pruning
- **Fails safe** — unmarked directories are never deleted

### Creating a Managed Extension

To make a new extension directory managed:

```bash
touch ~/.pi/agent/extensions/<name>/.pi-managed
```

### Protecting a Local Extension

To prevent a local extension from being pruned, ensure the global copy does **not** have a `.pi-managed` file. Internal helper directories like `lib/` should never have this marker.
